# LLM 裁判人工校准

LLM 裁判不能因为“看起来合理”就直接进入批量评测。本流程先抽取 12 条真实执行结果做人工金标，再让独立裁判 Prompt 打分；只有达到一致性门槛，才允许把裁判用于后续批量回归。

## 已确定口径

| 项目 | 口径 |
| --- | --- |
| 校准样本 | 12 条：8 典型、3 边界、1 攻击 |
| 样本来源 | 只从真实运行、条件已触发、结果完整的开发集中抽取；不使用 8 条留出集 |
| 抽取方式 | 运行前固定为 `L01、L02、L10、L12、L13、L18、L23、L26、L28、L31、L35、L38`；不按人工结论或模型结论挑选 |
| 人工评分 | 六个维度各填 0 或 1，并独立确认红线；六项全为 1 且红线为 0 才是 passed |
| 裁判模型 | DeepSeek，独立请求、独立裁判 Prompt |
| 评分粒度 | 六个评分维度各调用一次，红线单独调用一次 |
| 放量门槛 | 单条通过/失败一致率 ≥85%，红线判断 100% 一致 |
| 未达标处理 | `not_calibrated`，后续 LLM 结果不能作为批量评测结论 |

当前裁判 Prompt 版本为 `travel-judge-prompt/1.2.3`。每个维度独立返回 0 或 1；运行结果记录请求模型、供应商实际返回模型、每次请求 ID、Token 用量和可计算的模型成本，便于后续比较不同裁判版本。1.2.3 把 R04 拆成合同式检查：少走路不得用驾车距离反推；用户保持景点不变时，重生成或雨天切换直接命中，不依赖旧景点快照。

人工样本中同时保留人工判定通过与失败的案例，不能只挑“人工合格”的案例来制造高一致率。正确含义是：人工评分完成且有效，再判断 LLM 是否复现同样结论。

## 操作流程

先运行固定的 12 条真实校准评测，并确认结果中包含最终用户可见方案和轨迹：

```powershell
npm run eval:live -- --suite calibration --confirm-costs
```

生成 12 条校准样本和人工评分 CSV：

```powershell
npm run judge:prepare
```

填写 `artifacts/evaluations/judge-calibration-human.csv` 中的六个分数、红线结论、审核人、时间和备注。然后校验：

```powershell
npm run judge:review
```

只有 12 条全部完成时才会生成 `judge-calibration-ready.json`。确认愿意产生模型费用后再运行：

```powershell
npm run judge:run -- --confirm-costs
```

裁判会执行 `12 × (6 个维度 + 1 次红线) = 84` 次独立模型调用。结果写入 `artifacts/evaluations/judge-calibration-result.json`。

## 批量机评

只有完整 40 条真实 Agent 结果就绪，并且校准结果中的 Prompt 版本和指纹与当前裁判一致时，才能运行：

```powershell
npm run eval:live -- --suite full --confirm-costs
npm run judge:batch -- --confirm-costs
npm run judge:report
```

`judge:batch` 会重新检查四个条件：校准结论为 `calibrated`、决策一致率至少 85%、红线一致率 100%、40 条用例与固定清单完全一致。裁判 Prompt 变化后，旧校准自动失效。每条可评分用例执行六个维度加一次红线判断；未触发真实条件、执行异常或缺少最终输出的用例记为 `not_evaluated`，不从期望行为、Mock 或故障注入补分。

批量结果写入 `artifacts/evaluations/llm-judge-40-result.json`，可读报告写入 `artifacts/evaluations/llm-judge-40-report.md`。结果同时保留 Agent 请求 ID、Token 成本、模型/Prompt/工具版本，以及裁判请求 ID 和独立成本。

## 一致性判定

- 单条一致：人工 `passed/failed` 与 LLM 按同一 0/1 规则得到的 `passed/failed` 相同；双方都要求六项全为 1 且红线为 0 才通过。
- 红线一致：两边识别出的红线编号集合完全相同；漏检和多报都算不一致。
- 放量条件：12 条样本完整、至少 11 条单条结论一致、12 条红线判断全部一致。
- 即使总分接近，只要通过/失败或红线结论不同，也不能算该条一致。

## 数据与独立性

- 裁判输入包含用户原始输入、期望行为、自动检查、Agent 最终结果和相关轨迹。
- 裁判 Prompt 不包含人工分数、人工结论或人工备注，避免标签泄漏。
- DeepSeek 同时承担规划与裁判时属于同模型独立调用，仍可能存在同类偏差；报告中必须保留这一限制。更换为其他模型或完成人工抽检后，才能声称更高独立性。
- 当前产品运行和网页不允许调用裁判；所有裁判命令均只在命令行执行。
