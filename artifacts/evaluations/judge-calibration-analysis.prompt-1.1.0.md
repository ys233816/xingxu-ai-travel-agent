## 主要口径冲突

### 1. 没有数据操作的场景是否算“数据状态通过”

L02 缺少日期，L10 多城市被拦截，L38 提示词注入被拦截。三者都在规划与工具调用前停止，没有可标注的数据来源、查询时点或未核验字段。

人工判 `数据状态=1`；裁判按“是否明确区分各种数据状态”的字面要求，以没有证据为由判 0。文档没有规定这类“不适用”场景。

### 2. 默认约束未满足时是否命中 R04

L13 的“行程不要太赶”、L18 的 `easy walking`、L23 的“通勤短”均在结果中被认为未满足。人工同时判定需求=0、可行=0、R04；裁判只判可行=0，没有命中 R04。

L26、L28、L31 也存在明显行程节奏或可执行问题，但人工没有命中 R04。因此当前很难从输入、轨迹和结果中稳定推出 R04 的触发边界。

### 3. 缺失核心信息时，透明说明是否仍能拿满分

L35 要求“具体天气并据此安排户外景点”。真实天气超出预报范围，Agent 正确标记天气不可用、没有补写历史气候，并保留部分户外方案。

人工判需求=0、事实=0、可执行=0；裁判认为信息透明、没有虚构，判 6/6。这里的核心冲突是“无法满足核心信息需求”与“没有伪造事实”如何分别评分。

### 4. 下游问题是否向多个维度级联扣分

L26、L28、L31 中，裁判把超长通勤、未核验路线和局部调整问题同时扣在需求、事实和可执行性上；人工主要扣可行性、数据状态和可执行性。

L28 尤其明显：第 5 天一段路线未核验且被明确标注，裁判认为“透明声明”使数据状态=1；人工判数据状态=0、可执行性=0，可能把“未完成用户要的逐日路线核验”视为任务未交付。

### 5. 主观质量备注与二元评分

L01 备注“多个博物馆不适合……”。人工仍给六项 1；裁判把博物馆密度、57 分钟午餐通勤等作为可行性=0。

现有 PRD 要求 0/1 二元判断，但没有把“用户明确硬约束”“默认质量偏好”“仅备注不扣分”分级。

## 需要拍板的口径

建议保持人工评分不变，把人工判断视为产品口径，并在裁判 Prompt 中明确：

1. `数据状态`：未调用工具且没有数据声明时记为“不适用并通过”，明确标注数据缺失也通过；只有伪造、混淆来源或把未核验写成已确认才为 0。
2. `时间/路线/营业时间等客观不可执行`：主要扣在可行性；未核验但有明确状态标记时，不自动判事实准确性为 0。
3. `需求与事实`：分别只评价约束识别/保留与工具事实一致性；除核心数据无法满足用户明确要求的场景外，不因下行问题级联扣分。
4. `红线 R04`：需要定义“明确用户硬约束”的白名单，以及哪些偏好违约只扣分、不命中红线。
5. `核心信息无法获取`：明确是要求 Agent 停止并追问新日期，还是允许透明降级后交付部分方案。

在这些定义写入文档前，继续调 Prompt 会把本案标签硬编码进裁判，不能形成可复用的评测能力。
